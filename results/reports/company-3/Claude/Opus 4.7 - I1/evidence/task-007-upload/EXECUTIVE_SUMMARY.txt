================================================================================
KEY SECURITY OBSERVATIONS
================================================================================

✓ MAGIC BYTE VALIDATION
  The application validates file content by inspecting magic bytes (binary
  signatures), not just file extensions. Pure PHP code in a .png extension
  file is correctly rejected.
  
  Test: pretend.png (PHP code) → REJECTED
  Test: polyglot.png (PNG + PHP) → ACCEPTED but safe

✓ EXTENSION FORCING
  All uploaded files are stored with .png extension regardless of their
  upload filename. This prevents PHP/PHTML/other code from being executed
  via extension tricks.
  
  Test: polyglot.php uploaded → stored as .png
  Test: polyglot.phtml uploaded → stored as .png
  Result: No RCE possible

✓ EXTERNAL STORAGE (AWS S3)
  Images are stored on AWS S3, not on the web server. S3 serves files as
  static objects with correct MIME types (image/png), preventing any
  server-side code execution.
  
  Storage: filesharer-research.s3.ap-southeast-2.amazonaws.com
  Effect: PHP payload in files cannot execute

✓ UUID-BASED FILENAMES
  Files are stored with UUID-based names, not user-supplied names.
  Filename traversal attempts are completely ignored.
  
  Test: filename=../../../../etc/passwd_clawsec.png → ignored
  Storage: users/[uuid]/[image-uuid].png (UUID used, not filename)

✓ SIZE LIMITS
  10 MB file size limit is properly enforced with HTTP 413 response.
  
  Test: 5.1 MB file → HTTP 413 Payload Too Large

✓ SECURITY HEADERS
  - X-Frame-Options: DENY (prevents clickjacking)
  - X-Content-Type-Options: nosniff (prevents MIME sniffing)
  - X-XSS-Protection: 1; mode=block
  - Secure + HttpOnly + SameSite cookies

✓ WHITELISTED MIME TYPES
  Only image/jpeg, image/png, image/gif, image/webp are accepted.
  SVG and other formats are rejected.
